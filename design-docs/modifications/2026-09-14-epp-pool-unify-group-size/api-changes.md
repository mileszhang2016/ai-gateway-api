# /epp-pool 统一组规模校验 API 变更说明

变更记录：`change-summary.md`。接口：`/epp-pool`（`GET` 详情 + `PATCH` 全量替换，见 `api-define/OpenAPI接口定义/epp-pool.md`）。

## 1. 变更点

### 1.1 数据模型"约束"节（第 53 行）

**原：**

> - 每组实例数：生产环境每组恰 2 实例（主备）；测试环境允许单实例组（仅主、无备）；校验强度由部署形态配置项控制。

**新：**

> - 每组实例数：1 个（仅主）或 2 个（主+备）；拒绝空组与 3 个及以上实例的组。不再按部署形态（production/test）区分校验强度。

### 1.2 PATCH"约束"节（第 135 行）

同 1.1 改写。

### 1.3 PATCH"执行逻辑"（第 161、164 行）

- 第 1 步"校验请求参数合法性（…、组规模）"：措辞不变，组规模校验语义变为"每组 1~2 个实例（1=仅主，2=主+备）"。
- 第 4 步分配悬空自动修复：分支②条件"组已不存在（或组规模不再满足部署形态要求）"简化为"组已不存在"——单实例组不再触发跨组重分配。

## 2. 兼容性

| 维度 | 影响 |
|------|------|
| 请求字段 | 无变化（`groups[].name` / `groups[].instances[].id/host/port` 均不变） |
| 响应字段 | 无变化 |
| 校验变化（双向） | 放宽：原 production 模式下单实例组返回 422 → 现返回 200；收紧：原 test 模式下 3 个及以上实例的组返回 200 → 现返回 422 |
| 配置项 | `RunTime.EPPValidationMode` 删除；旧配置文件残留该键可正常启动（toml 非严格解码，静默忽略） |
| 导出格式 | `EPPAddr`/`epp_data` 单实例组导出 primary-only 的行为此前已在 test 模式存在，格式不变 |
