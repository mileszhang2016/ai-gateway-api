# OpenAPI v0.3.0 优化改造 - AI 协作提示词记录

## 一、背景与目标

本次改造对 `ai-gateway-api` 的 OpenAPI 层进行接口收敛与规范化调整，最终形成一套与代码实现一致的接口定义、系统设计及集成测试方案。

文档版本管理策略：后续设计文档本身不再维护独立的版本号，版本信息统一跟随 Git 版本号管理。

## 二、改造范围

- `design-docs/modifications/2026-07-27-openapi-optimize/`：变更分析与方案文档
- `design-docs/api-define/`：OpenAPI 接口定义文档
- `design-docs/sys-design/`：系统设计文档
- `ai-gateway-api` 源码
- `test/docs/README.md`：集成测试总体方案
- `test/integration/tests/`：各模块测试方案与测试代码

## 三、关键原则

1. **以差异分析为准**：先生成 `api-changes.md` 明确当前版本与目标版本的差异。
2. **以代码实现为最终依据**：接口定义和文档修改需与代码实际行为保持一致。
3. **不直接参考目标版本草稿**：`瑛菲AI网关-OpenAPI接口定义v0.3.0.md` 仅用于差异对比，不作为修改 `design-docs/api-define` 和 `design-docs/sys-design` 的直接依据。
4. **文档去版本号**：从 `design-docs/api-define` 和 `design-docs/sys-design` 中删除文档版本号及版本历史信息。
5. **测试同步更新**：集成测试范围、测试方案、测试代码随接口变更同步刷新。

## 五、关键决策记录

| 决策点 | 结论 |
|--------|------|
| `/expression/verify` | 保留，不删除 |
| `ErrNum=510` | 不新增到 OpenAPI 文档 |
| `GET /api-keys` 返回结构 | 保持分页结构，不改数组 |
| 删除证书接口返回 | 保持原返回内容，不改为 `Data=null` |
| 查询单个用户 / 系统导航配置 | 保留 |
| `POST /auth/users` 的 `is_admin` | 从必填改为选填，且仅支持 `true` |
| 文档版本号 | 从设计文档中移除，统一由 Git 管理 |
| 废弃模块目录 | 删除 `ai_route/`、`model_provider/` |
