# 限流策略与导出

## 1. 概述

限流策略用于控制 API-Key 或 Entity 对后端 AI 模型的访问速率。策略支持三类限制：

- **TPM**（Tokens Per Minute）：每分钟 Token 消耗上限；
- **RPM**（Requests Per Minute）：每分钟请求次数上限；
- **并发数**（Max Concurrency）：同时处理的请求数上限。

每个 API-Key 或 Entity 可绑定一个限流策略；在导出到 BFE 时，策略按 Entity 层级向上合并，最终生成 `rate_limit_policies` 与 `api_key_rl_policy_bindings` 两类配置。

---

## 2. 数据模型

### 2.1 表结构

```sql
CREATE TABLE rate_limit_policies (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description VARCHAR(255) DEFAULT NULL,
    product_name VARCHAR(255) NOT NULL,
    enabled TINYINT(1) NOT NULL DEFAULT 1,
    max_concurrency INT DEFAULT NULL,
    tpm_configs JSON DEFAULT NULL COMMENT 'TPM 配置数组',
    rpm_configs JSON DEFAULT NULL COMMENT 'RPM 配置数组',
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 2.2 JSON 字段结构

#### `tpm_configs`

```json
[
    {
        "model": "gpt-4",
        "limit": 100000
    },
    {
        "model": "*",
        "limit": 500000
    }
]
```

#### `rpm_configs`

```json
[
    {
        "model": "gpt-4",
        "limit": 1000
    },
    {
        "model": "*",
        "limit": 5000
    }
]
```

`model` 支持具体模型名或通配符 `*`（表示默认限制）。

type RateLimitPolicy struct {

## 4. 创建与更新

### 4.1 校验规则

`RateLimitPolicyManager.CreateRateLimitPolicy` / `UpdateRateLimitPolicy` 会执行以下校验：

1. `product_name` 必须非空且存在；随着 Product Scope 收敛，OpenAPI 不再要求传入，建议存储层默认填充为 `AI_product`。
2. `name` 在产品内唯一；
3. `max_concurrency` 必须 ≥ 0（为 0 时 BFE 可能视为不限制或禁止，取决于 BFE 实现）；
4. `tpm_configs` / `rpm_configs` 中的 `model` 不能为空；
5. `limit` 必须 ≥ 0。

### 4.2 启用/禁用

- `enabled = true`：策略生效，会导出到 BFE；
- `enabled = false`：策略不导出；若已被 API-Key 或 Entity 引用，导出时该绑定也会跳过。

## 6. 导出到 BFE

### 6.1 入口

```go
func (m *RateLimitPolicyManager) RateLimitPolicyGenerator(ctx context.Context) (*iversion_control.ExportData, error)
```

### 6.2 导出流程

```
1. 查询所有 API-Key
2. 查询所有 RateLimitPolicy
3. 对每个 API-Key：
   a. 收集 API-Key 自身 policy_id
   b. 递归收集 Entity 层级向上的 policy_id
   c. 跳过 enabled=false 的策略
   d. 为每个启用的 policy_id 生成绑定关系
4. 将所有启用的策略写入 rate_limit_policies.json
5. 将所有绑定写入 api_key_rl_policy_bindings.json
```

### 6.3 Entity 层级递归

```go
func (m *RateLimitPolicyManager) fetchEntityRateLimitPolicyIDs(ctx context.Context, entity *EntityParam) ([]int64, error) {
    policyIDs := make([]int64, 0)
    if entity.RateLimitPolicyID != nil {
        policyIDs = append(policyIDs, *entity.RateLimitPolicyID)
    }
    if entity.ParentID != nil && *entity.ParentID != "" {
        parent, err := m.entityStorager.FetchEntity(ctx, &EntityFilter{EntityID: entity.ParentID})
        if parent != nil {
            parentPolicyIDs, _ := m.fetchEntityRateLimitPolicyIDs(ctx, parent)
            policyIDs = append(policyIDs, parentPolicyIDs...)
        }
    }
    return policyIDs, nil
}
```

### 6.4 绑定生成

```go
for _, policyID := range policyIDs {
    policy, exists := allPolicies[policyID]
    if !exists || policy.Enabled == nil || !*policy.Enabled {
        continue // 跳过未启用或已删除的策略
    }
    binding := APIKeyRateLimitPolicyBinding{
        Apikey: apiKeyValue,
        Policy: fmt.Sprintf("rlp-%d", policyID),
    }
    bindings = append(bindings, binding)
}
```

只有 `enabled=true` 的策略才会被写入 `rate_limit_policies.json` 并生成绑定；导出结构中的 `Enabled` 字段固定为 `true`。

### 6.5 策略命名

导出的策略名称统一格式为 `rlp-<policy_id>`，避免命名冲突并便于 BFE 索引。

### 6.6 导出文件

| 文件名 | 内容 |
|--------|------|
| `rate_limit_policies.json` | 所有启用状态的限流策略 |
| `api_key_rl_policy_bindings.json` | API-Key 到策略的绑定关系 |

## 7. BFE 侧预期行为

BFE 收到配置后：

1. 根据 `api_key_rl_policy_bindings.json` 找到 API-Key 对应的策略列表；
2. 请求到达时，按模型匹配 `tpm_limits` / `rpm_limits`：
   - 优先匹配具体模型名；
   - 未命中时使用 `*` 默认限制；
3. 同时检查 `max_concurrency`；
4. 任一限制超出时返回 429 Too Many Requests。

> BFE 具体计数器实现（Redis / 本地内存 / 滑动窗口）不在本文档范围。

## 8. 边界情况

| 场景 | 行为 |
|------|------|
| API-Key 与 Entity 都未绑定策略 | 不生成绑定，BFE 对该 Key 不限流 |
| 策略被禁用 | 不导出策略，也不生成绑定 |
| 策略被删除但仍有引用 | 导出时跳过该策略 ID，引用方不受影响（视为未绑定该策略） |
| 同一策略在层级中多次出现 | 生成多条绑定记录；BFE 去重或按命中顺序处理 |
| `max_concurrency = 0` | 取决于 BFE 语义：可能表示禁止并发或无限并发，需与 BFE 对齐 |
| `tpm_configs` / `rpm_configs` 为空 | 仅限制并发数 |

---

## 9. 设计建议

1. **策略命名可配置**：当前强制 `rlp-<id>`，建议允许用户自定义导出名称或别名。
2. **去重绑定**：Entity 层级中若同一策略出现多次，导出时可去重以减少 BFE 配置量。
3. **限流与配额顺序**：建议在 BFE 中先校验限流、再校验配额，避免配额被无效请求消耗。
4. **限流超限提示**：返回 429 时可在响应头中增加 `Retry-After`，提升客户端体验。
