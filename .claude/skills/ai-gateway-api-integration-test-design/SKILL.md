# AI Gateway API 集成测试例设计方法论

本 Skill 是 `ai-gateway-api-rd-workflow` Phase 6/7（集成测试设计与实现）的配套检查清单。核心命题来自一次历史复盘：**缺陷漏到 QA 的根因不是"没写测试"，而是测试存在系统性盲区**——用例只测合法路径、只断言"提交的字段生效"、断言依据实现而非合同。

## 触发语

- "帮我给 `<模块>` 补/写集成测试"
- "为这个功能设计集成测试用例"
- "评审一下这批集成测试用例是否足够"
- rd-workflow Phase 6 设计测试场景时逐条过本清单

## 使用原则

1. **断言以合同为唯一依据**：写用例前先读 `design-docs/api-define/` 对应接口定义。实现与合同矛盾时，先停下来确认"修代码还是修合同"，**绝不按实现现状写断言**（按实现写的断言会把缺陷固化成"通行证"——issue #202 的单测 `assert.Empty`、#115 的 PV-1-001、#170 的 MP-5-001~003 都是反面教材）。
2. **每个 4xx 用例都要带"回读零变更"断言**；每个 PATCH/PUT 用例都要带"未提交字段不变"断言。
3. 每条检查项后的 issue 编号是真实缺陷证据，可在 `design-docs/modifications/` 查到完整案例。

## 核心检查项（12 个缺陷家族）

### 1. PATCH/PUT「省略字段保留原值」矩阵 —— 历史最高频家族

证据：#147、#151、#152、#140、#82、#201

- 对每个支持 PATCH/PUT 的资源：创建时显式设置所有可选字段为非默认值 → PATCH 只改一个无关字段（如 description）→ GET 断言**所有未提交字段原值不变**。
- 必做「省略 vs 显式空」对照：PATCH 显式传 `models:[]` 应清空，省略应保持原值——两者结果不同才是对的。
- map 型字段（如 model-prices 的 prices/tier_prices）要下钻到键级：PUT 只改一个键，断言未提交键保留、未出现的子档整档保留。
- 副作用变体（#82）：body 携带嵌套对象（quota_plan）但只改外层无关字段时，断言配额余额 used/remaining 不变、Redis 剩余量不重置。

### 2. PUT/PATCH 对称性对照

证据：#199（f2c73d8 给 create/PATCH 补了 entity 存在性校验，漏了同目录 full_update.go）

- 同一资源的 PUT 与 PATCH 携带**相同 body** 各执行一次，断言响应码与错误消息逐字一致。
- 凡 PATCH 有的校验（引用存在性、字段合法性），PUT 必须有；反之亦然。
- 给 A 接口补校验/修缺陷时，同族接口（create / update / full_update）必须逐一对齐回归。

### 3. 4xx 拒绝路径的「回读零变更」断言

证据：#156（假事务：返回 409 但修改已持久化）、#199、#172、#173

- 每个负向用例（422/409/404）在断言拒绝后，必须 GET 读回被操作资源，断言与操作前**逐字段一致**（含嵌套配置）。
- 能拦截两类缺陷：校验放错层（先写库后校验）与事务失效（rollback 未覆盖真实写路径）。此类行为 fake storager 单测结构性够不着，只能靠真实进程的集成测试。

### 4. 非法值/边界值矩阵 + 错误归因 + 防泄漏

证据：#172、#173、#133、#81

- api-define 中每条校验规则至少一个负向用例；数值字段覆盖 0、负值、超上限、边界±1；字符串字段覆盖字符集白名单与长度边界。
- 断言错误码（422/受控 4xx）且错误消息可归因到具体字段。
- **防泄漏断言**：被拒绝的配置不得出现在 InnerAPI 导出产物中（#172 的非法 uri 曾导致 BFE reload 失败、阻塞全部下发）。
- 字符集校验收紧时，必须同时补真实使用模式的正向用例（#135：用户名 `user@project` 形态）。

### 5. 跨对象引用存在性与引用完整性（双向）

证据：#199、#106、#106-followup、#115

- 正向：POST/PUT/PATCH 携带不存在的 entity_id / provider / cluster → 4xx。
- 反向（悬空引用）：cluster 引用 provider 的 key/model 后，PATCH provider 删除或重命名被引用项 → 409 且 provider 自身读回不变。
- 变更传播：PATCH provider instance_pool 后，InnerAPI 导出的 cluster_table backends 须在超时内收敛为新值，且未引用该 provider 的 cluster 不受影响（#106 的 PV-SYNC-1-001 模式）。

### 6. 更新副作用与运行时状态连续性

证据：#84、#169

- 改名称/描述类字段不得重置运行时状态：限流计数器同窗口连续（改名后仍 429）、配额余额连续。
- 按现行合同补重命名语义用例：PATCH 改名 200 通过后，断言旧计数 key 被清理、新 key 从零开始。

### 7. 审计/操作日志断言

证据：#161、#155、#162、#185、#201、#183（全部本可在开发期拦截）

- 嵌套资源（随 api-key/entity 创建的 quota_plan、rate_limit_policy）必须产生审计日志，且 `resource_parent_id` 归属父资源业务 ID。
- 失败路径（4xx）也要记审计，且 `resource_id`/`resource_name` 取自库中快照或 URI，不依赖请求体是否携带（#155：极简 body 失败时身份丢失）。
- `diff_keys` 用**精确匹配**（ElementsMatch），禁止 Contains——Contains 对幻影键不敏感（#201）。
- 敏感字段脱敏：token、API Key 明文、provider `keys[].key` 不得出现在 change_summary 与 error_msg；断言方式是把整条日志 JSON 序列化后检查不含明文（#162、#185）。
- 错误码语义：管理写操作只允许 2xx/4xx，出现 500 即缺陷（#183：unlimited reset 返回裸 error 被兜底成 500）。

### 8. InnerAPI 导出/编译产物断言

证据：#106、#181、#198、#142、#102

- 控制面承诺给数据面（BFE/EPP）的每个字段都要断言其**存在性**与取值（如 epp_config 的 `strategy`、`priorityBands`——漏字段时下游默认值可能与文档语义相反）。
- 全局配置与等效容量联动（#198：全局 max_requests=200 时 band0 不得落到下游隐藏默认 5000）。
- 版本单调（#142）：同一秒内连续两次变更，导出版本号必须严格递增，有限轮次内收敛。
- 数值字段对**原始 HTTP body 文本**断言（#102）：8 位小数价格不得序列化为科学计数法（仅反序列化值比较会静默通过）。

### 9. 数值精度与口径回归锁

证据：#102、#207

- 价格/金额类字段同时断言文本形态（不含 `e-`）与反序列化值。
- 定点数换算出口加"口径回归锁"：同种子数据下，旧口径为 ≥1 整数时新口径必为同量级小数（#207：66900 → 0.000669，断言 0<value<1 区间即可锁死回归）。

### 10. 并发用例（MySQL 环境，build tag 隔离）

证据：#80、#99、#132

- 开发期集成为 SQLite，结构性无法测并发——这是已知盲区，但用例必须落盘（`//go:build mysql` 标签），CI 或手工用 MySQL 跑。
- 模式：N 个 goroutine（20~100）不带 id 并发 POST 创建 → 全部 2xx、id 集合无重复、无 500 / lock wait timeout / deadlock、单请求耗时可接受。
- **修并发缺陷后必须用同模式回归**——#99 就是 #80 的修复自身在 MySQL RR 下引入的回归。

### 11. 查询/过滤行为按合同做参数矩阵

证据：#170、#191

- 按 api-define 对查询参数组合做矩阵：组合键齐全 → 单对象；缺参 → 422 或回落列表（以合同为准）；未命中 → 404/空列表。
- 对返回形状断言**顶层键**（单对象 vs `list+pagination`），防止客户端按单对象解码静默得到全零值。
- 环境相关行为（如 report 分区 JOB）要在真实 MySQL **非空 schema** 名下测；不要用空库名单测构造糊弄（#191：单测全用空库名，生产非空库名路径恒错）。

### 12. 合同一致性核对（防测试固化缺陷）

证据：#169、#186、#115

- 发现实现与合同矛盾时：先确认是修代码还是修合同，再写/改用例；合同修订后要有用例锁定新语义、删除旧语义用例。
- 典型形态：合同写"创建后不可修改"但接口放行（#169）；合同条款从未实现（#186 死条款）；合同非必填但接口间约束要求尽早失败（#115）。

## 用例编写约定（对齐 test/integration 现状）

- 用例编号：`<模块>-<接口序>-<三位序号>`，如 `AK-4-006`（api_key/full_update 第 6 例）；编号在模块 design.md 场景总览表中先登记。
- 流程：先在 `test/integration/tests/<module>/design.md` 补详细设计（前置数据、步骤、请求参数、预期结果），再实现 `_test.go`。
- 资源命名：run-scoped 唯一（如 `sc1301-tc028-missing-entity-<runID>`），避免并发/重跑污染。
- 涉及 OpenAPI 响应字段时在 `tests/schema/openapi/<module>.go` 补 schema；涉及 InnerAPI 导出字段时在 `tests/schema/innerapi/` 补断言。
- 命令：
  ```bash
  cd ai-gateway-api && go build -o ai-gateway-api.exe .   # 先重建二进制，否则测的是旧服务
  cd ai-gateway-api/test/integration
  go test -v -count=1 -timeout 300s ./tests/<module>/...
  ```
- MySQL 并发用例：文件头 `//go:build mysql`，`go test -tags mysql ./tests/...`，需自备 MySQL 连接串。
